# Using the MimicryMap mimicry coverage summaries

## Canonical reference downloads

The first population in Target → comparison supplies the rows. Reversing the direction changes the target sequence and coverage denominator. Every Swiss-Prot reference population contains all 20,431 human Swiss-Prot records, including short proteins. The seven tables cover Swiss-Prot self-comparison; both directions versus canonical exposures and the 120-virus atlas; and both directions versus non-vertebrate exposures. Plot eligibility affects figures only. Hormone-only supplements remain available in the interface, with no separate standard export variant.
The standard human reference is UniProtKB/Swiss-Prot release 2026_01 (January 28, 2026), with 20,431 reviewed records. The broader human library in the interface also includes 339 retained TrEMBL records and 218 additional HORDB peptide-hormone sequences, for 20,988 records. The hormone scope includes ten further proteins already present in Swiss-Prot. UniProt supplies sequence annotations and variants; GO supplies fallback cellular-component assignments. AlphaFold, FreeSASA and pepsickle provide the structure, accessibility and cleavage tracks described on Data & Licenses. Available target annotations travel with Current Comparison in a separate metadata file; population FASTAs contain sequences and headers.
Canonical exposures combines UniProt Allergome-tagged proteins (4,016 source records), the IEDB human-exposure positive protein-antigen selection downloaded September 1, 2026 (19,621 sequence-bearing source records), the 120 curated viral proteomes (2,222 records), and 8,826 retained exposure reference records. The retained collection includes allergen, IEDB, viral and other exposure proteins, including 16 supplementary UniProt records; twelve updated sequence records are also retained. Identical amino-acid sequences are merged while retaining source memberships, yielding 24,867 sequence records. Source counts overlap and must not be added. The viral atlas is a subset of this combined collection.
The IEDB selection excludes Primates (including humans) and non-protein antigens; sequence-bearing records enter the comparison population. It describes antigens associated with positive responses, not individual assay reactions. All canonical exposures includes non-primate mammalian proteins. The two non-vertebrate downloads use 21,689 records with at least one resolved non-vertebrate source, retaining sequences shared with vertebrates. Mammals, birds, reptiles, amphibians and fish are excluded unless another source provides resolved non-vertebrate provenance. Records with only unresolved taxonomy are excluded. See Data & Licenses for citations and licenses.
The viral atlas uses 2,222 protein records across 120 curated viral proteomes. Standard exports use the complete Swiss-Prot population without a length or plotting-eligibility filter. Scope nests Vertebrates and Mammals beneath Eukaryotes. Uncheck Mammals to exclude mammalian-only records, or Vertebrates to exclude vertebrate-only records and turn off both nested selections. The standard filtered downloads use the latter population in both directions and exclude controls and records with only unresolved taxonomy. Swiss-Prot-only excludes supplemental hormone-only and TrEMBL records but retains Swiss-Prot proteins that themselves have hormone-related annotations.

## Assay library summaries and antibody-data identifiers

The nine assay comparisons cover **21,197 HuProt 4.0 protein constructs**, **731,724 HuScan peptides**, and **680,704 VirScan/Exposome peptides**. VirScan/Exposome combines the full VirScan library, including viruses of nonhuman hosts, with the Exposome add-on. Downloads retain all 680,704 records, including 31 controls; the default mapping Scope excludes controls and shows 680,673 records across its three selectable subsets. Available comparisons are HuProt self, HuScan–HuProt in both directions, VirScan/Exposome against each human assay library in both directions, and HuProt against the 120-virus atlas in both directions. The latter two use the 2,222-record viral atlas subset, not all canonical exposures. These use the same 22-column comprehensive format and identity thresholds as the reference tables.
Use the original assay ID to join a row to multiplex antibody measurements. **Antigen Target Protein Description** starts with its **JHU ID** for HuProt or **CDI ID** for HuScan and VirScan/Exposome, followed by the retained description when present. Mimicry Parent lists retain the corresponding partner IDs. For example, `JHU00001`, `CDIH20000001` and `CDIV20000001` identify individual assay records; gene names and accessions may recur across different records.
Assay FASTAs preserve the original catalog headers, with the assay ID before the first `|`, and the exact stored sequences. Coverage uses each assayed construct or peptide's own length. Distinct records remain separate even when they share a sequence or accession. These CSVs contain sequence comparisons to align with antibody data, not antibody measurements. See [CDI Labs assay resources](https://www.cdilabs.com/resources/literature?page=1&category=content) for assay background.
Public filenames use `huprot4`, `huscan` and `virscan_exposome`, with single underscores between filename components. Displayed comparison names are HuProt 4.0, HuScan and VirScan/Exposome. Original record identifiers remain unchanged.

## What the tables contain

The current whole-library summary has 22 columns, with all three thresholds in one file. Target full sequence, metadata, All Matching Parent Count, Shared Regions and Uncovered Residue Regions are retained. Parent sequences are not embedded; use the parent IDs to cross-reference the comparison FASTA or database. Each target row includes gene, accession, description, full sequence, organism/taxon label, comparison library, and column groups at minimum 7/9, 8/9 and 9/9 identity in an ungapped nine-residue core. There is no new sequence search when reading these files.
Coverage counts the union of residues in qualifying nine-residue cores, including mismatches; overlapping residues count once. Flanking context is excluded. The denominator is the full target or parent sequence length.

### Shared and uncovered residues

**Shared Regions** is the union of target residues covered by qualifying windows. **Uncovered Residue Regions**: Target residues outside all qualifying 9-residue windows at the stated identity threshold and comparison scope. Qualifying windows include mismatch positions; uncovered residues may participate in lower-identity matches.
Coordinates are 1-based and inclusive (`start..end`); flanking context is excluded. These fields use the same identity threshold and comparison scope as coverage and the residue plot. A 20-residue target covered only at residues 1–9 has Shared Regions `1..9` and Uncovered Residue Regions `10..20`.
A qualifying 5/9 window covers all nine positions, including its four mismatches. Overlapping windows count each residue once. At 7/9, uncovered residues may still participate in 5/9 or 6/9 matches. Reversing processing order does not change the union. Both sequence ends belong to fewer complete windows than internal residues; neither end is preferred. These interval columns describe the target. Parent coverage uses the corresponding parent coordinates; reversing target and parent changes the sequence and denominator.
Records shorter than nine residues remain present and are labeled Not assessable (<9 AA), with blank coverage. Self-comparisons exclude the same physical record while retaining other records with identical sequences.

## Read Mimicry Parent lists and choose cutoffs

At each identity level, **Mimicry Parents at 7/9 with Coverage (%) Parent|Target (>=10% either)** (and the corresponding 8/9 and 9/9 columns) records entries as `label@parent_percent|target_percent`, separated by semicolons. For example, `DGUOK|Q16854-2|JHU11068@25.9|55.1`. Label components are gene (or the existing organism fallback), accession, then assay ID, joined by `|` without surrounding spaces. Missing components are omitted. Original identifier values remain intact. The order is always **Parent|Target**.
Lists retain every pair reaching at least 10% coverage on either endpoint at that identity level. Inclusion is inherited from the existing numeric summaries before rounding; a listed parent's other endpoint may be below 10%. Pair percentages have one decimal, rounded half-up from the original summary values. The preserved source summaries retain their original two-decimal precision for boundary-sensitive filtering. Overall target coverage, regions and counts are copied unchanged.
Parse outer CSV quoting first. Split unescaped semicolons between entries, then the unescaped `@` between label and percentages. The left side of `@` is the label: split its unescaped pipes into components. The right side contains exactly two numeric values separated by `|`. Structural pipes and `@` are unescaped; backslash escapes a literal backslash, semicolon, `@` or `|` inside a label component. Empty lists retain their target rows. Numeric zero is a rounded value, not missing data.
**All Matching Parent Count** includes every record with a qualifying match, even below the listing floor. The number of entries in the paired list is directly countable, so no separate Listed Parent Count column is exported. **Coverage (%)** describes aggregate target coverage across all qualifying parents, not just listed parents. Coverage values can differ between 7/9, 8/9 and 9/9 even when the same parent appears in each.
These tables describe sequence relationships and can supply candidate sets for downstream analyses; they do not contain antibody measurements or enrichment statistics.

## Current and retained formats

The whole-library download tables provide one comprehensive summary CSV per direction, alongside target and comparison FASTAs. There is no separate light-list column or identity/endpoint selector. The 22-column format retains the original seven target/comparison fields and, for each identity level, aggregate coverage, Shared Regions, Uncovered Residue Regions, All Matching Parent Count and one paired parent list.
The prior spaced-label 22-column summaries, previous 28-column summaries, original 34-column summaries and all earlier compact files remain unchanged at their original URLs for precision, provenance and recovery. The manifest's `comprehensive_summaries` block identifies the current 16 whole-library downloads (seven reference and nine assay directions); `summaries` and `assay_summaries` retain their bound 34-column source catalogs. Earlier comprehensive and selected-virus catalogs remain in `legacy_comprehensive_summaries`, `legacy_selected_summary_generations` and `legacy_selected_viruses`. Earlier compact generations remain in `masks`, `legacy_numeric_masks` and `legacy_masks`, with superseded status. The format migration preserved earlier files and did not rerun sequence comparisons; newly added comparison datasets have their own publication receipts.
The 240 contextual selected-virus downloads now use the same 22-column format. Browser/custom Summary CSV exports the same five fields for its selected identity level; the local pipeline exports groups for 7/9, 8/9 and 9/9. The browser/current-result/custom Summary CSV has 12 base fields for its selected threshold plus six annotation fields (18 columns). Local summaries have 22 base fields for all three thresholds plus six annotation fields (28 columns). Static downloads have 22 columns without those annotations. Target sequences are retained; parent sequences are obtained by database/FASTA cross-reference. The local package shares this field contract; matching the site's identities, grouping and annotations also requires the corresponding accepted input metadata, not FASTA alone.

## Spreadsheet or code?

Each CSV preserves complete fields in their original columns, including long sequences and parent lists. Import identifiers as text.

## Populations and reproducibility

The accompanying manifest supplies file sizes, row counts, SHA-256 checksums, identity thresholds and suggested coverage cutoffs. The Target FASTA and Comparison FASTA columns provide the full sequence populations associated with each CSV and retain each population’s identifiers. Reference FASTAs use accession, gene and protein-description headers; assay FASTAs use the original catalog headers beginning with JHU/CDI IDs. Each population FASTA comes from the corresponding public target rows; the non-vertebrate FASTA is the same population in both directions. Comparison FASTA includes the full comparison population, not only parents retained by the 10% list floor. Empty sequences, if present, are omitted from FASTA and reported in the manifest; short nonempty sequences remain.
The downloadable code package’s README and Input Guide explain how to run these populations, replace inputs, and use Current Comparison metadata. This dictionary describes the populations and output fields. Standalone FASTA contains sequences and headers; reproducing reference annotations and mapped record relationships also requires their metadata.
See How It Works for the matching method and Data & Licenses for source references and terms.

### Organism labels in summary CSVs

`Antigen Target Organism (TaxID)` identifies the organism and its NCBI taxon ID. Full source organism/strain names and their corresponding NCBI taxon IDs share one cell, with `; ` separating multiple source taxa. Exposure labels preserve the supplied source TaxID rather than replacing it with a species-level TaxID. The target library remains in the filename and manifest. Missing IDs are shown explicitly as `TaxID: not supplied`. Atlas-scoped rows use the full organism/strain name and matching taxon ID shown by the atlas page. Existing VirScan species and genus/family text remains in record labels.
App/local exports retain supplied `OS=` and `OX=` FASTA metadata and organism/taxon metadata in the Current Comparison sidecar. Bound human libraries use Homo sapiens (9606). Arbitrary FASTA inputs without taxonomy remain unspecified. Offline runs do not fetch taxonomy.
Short sequences retain `Not assessable (<9 AA)` in their region fields.

## One selected virus

The Pan-Viral Atlas offers both Human → virus and Virus → human CSVs for its selected viral proteome, alongside the pooled All viruses downloads. Each human-target file includes all 20,431 Swiss-Prot records. Its coverage, regions and parent counts are recomputed using only that virus; the reverse file retains the corresponding viral rows against the full human population. The contextual and pooled All viruses files use the same 22-column format and listing floor. The selected virus's organism/strain and TaxID identify the scope. No-match and short human records remain included.

### Selected virus and All viruses

The collection contains 240 selected-virus CSVs: two directions for each of the 120 reference proteomes. Selected virus refers to the reference proteome shown by the selector, including its organism/strain and TaxID; it does not combine every strain of that species. All viruses pools the declared atlas collection and is separate from the full canonical exposure library.
Human → virus supplies one row for each of the 20,431 Swiss-Prot human records, with only the selected virus as the comparison population. Virus → human supplies the selected proteome's viral rows against the full human population. The 20,333-record, ≥50-AA restriction applies to plots only. Human summary downloads retain short and no-match records.
The files are static downloads; changing the selector changes both links without starting a new comparison. The downloadable manifest's `selected_viruses` section records each proteome's identity and both URLs, row counts, byte sizes and SHA-256 checksums. The pooled tables remain available in the All viruses row.
Whole-target `Coverage (%)` describes the union across the selected comparison population. The paired `Coverage (%) Parent|Target (>=10% either)` lists describe individual pairs; their 10% listing floor does not filter whole-target coverage or All Matching Parent Count. Do not subtract pooled percentages or simply remove parent-list entries to reconstruct a selected-virus human summary.

### Separate research outputs

Virus-linked human gene sets derived from assay-tile comparisons use their own membership and reciprocal tile-coverage definitions. They are not interchangeable with these whole-protein summary percentages. Cohort antibody analyses and positivity audits are separate research outputs; an assay-positive label or sequence-defined set is not an enrichment result or evidence of imprinting. See each research output's own methods and completion status.
Current CSVs use UTF-8 with a byte-order mark (BOM), and column headers use ASCII `>=10% either`. This keeps headers readable in spreadsheet apps while preserving Unicode in record names. Python readers should use `encoding="utf-8-sig"`; parse CSV quoting before the escaped parent-list delimiters.
